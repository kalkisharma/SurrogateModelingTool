Surrogate Modeling Tool

Train a fast mathematical model on your CFD runs, then predict aerodynamic outputs for thousands of new design points without running the solver again — all data stays on your machine

How to use this tool

  1. Upload CSV — your CFD results table with one row per simulation run. Numeric columns only for inputs and outputs.
  2. Explore data (Step 1) — check input correlations, feature–output relationships, and flag unusual runs before training.
  3. Select columns — choose which columns are inputs (features) and which are outputs (targets). Confirm to clean the data.
  4. Configure & train (Step 2–3) — pick a model type (Linear, GPR, or Random Forest), train, then review parity plots, residuals, and feature importance.
  5. Predict (Step 4) — enter a single design point or upload a batch CSV to get predictions with uncertainty estimates. Use the sensitivity and surface plots to explore the response surface.

All data stays on your machine — no cloud connection required. Reopen this guide anytime from the header.

► What is a surrogate model? — click to learn before you start

A surrogate model is a fast mathematical approximation trained on a small set of CFD runs. Example: run 100 RANS simulations across your angle-of-attack and Mach number envelope, upload the results here, and the surrogate predicts CL and CD for 10,000 new design points in seconds — without queuing another solver job.

Works for any tabular simulation data: aerodynamic, structural, thermal, or propulsion. One row per simulation run, design parameters as input columns, outputs as separate columns.

Minimum data: 30+ simulation runs recommended. Gaussian Process Regression (GPR) works well from 30–500 rows. Random Forest from 100–2,000 rows.

⚠ Outlier Detection —

How it detects outliers: We measure the typical spread of each column using the interquartile range (IQR) — the gap between the 25th and 75th percentile values. Any data point more than the sensitivity multiplier × IQR above or below the middle bulk is flagged.

Sensitivity multiplier: 1.5× (mild) catches moderate anomalies and is good for clean wind tunnel data. 3.0× (strict) flags only extreme outliers — better for CFD sweeps that intentionally include stall or transonic conditions where large CD values are physically real and should be kept.

Why it matters for your surrogate: A single anomalous CFD run — a diverged solution or transcription error — can pull the fitted model away from your real operating envelope, reducing accuracy across the entire design space.

When to exclude: Exclude if the flagged row represents a numerical error or physically impossible condition. Keep it if it is a real edge-case design point — but expect lower surrogate accuracy in that region.

Input Correlations

What this shows: How strongly each pair of input features is correlated (Pearson r, −1 to +1). Red = strong positive correlation, blue = strong negative. 0 = no straight-line relationship (could still be nonlinear — check the scatter plots below).

Why it matters: Redundant inputs make the model harder to interpret. Consider removing one — but only if both are not independently meaningful for the physics.

What Your Model Will Learn

What this shows: Each input plotted against each output with a linear trend line (red). Points that follow the line closely → Linear Regression will handle this well. Points that curve away from the line → the relationship is non-linear, and GPR or Random Forest will perform better.

Wide scatter: Scatter around the line means noisy or complex data in that region. More CFD runs there would improve model accuracy.

Unusual Run Detector

What this shows: Simulation runs that are unusual as a combination of inputs, not just extreme in one column. A run can look normal in every individual input but still be an unusual combination (e.g. high Mach at very low AoA when all other high-Mach runs are at moderate AoA).

GPR Hyperparameters

RBF (Squared Exponential): Assumes your output changes smoothly everywhere — ideal for aerodynamic coefficients like CL and CD that vary continuously with angle-of-attack and Mach number. Start here.

Matérn ν=1.5: Allows slightly rougher transitions. Better when your response surface has localised non-linearities (e.g. near stall) or when measurements include noise.

Both kernels are auto-optimized during training — the choice of kernel affects only the assumed shape of the response surface, not how hard the optimizer works.

After normalisation, all features are on the same scale (std=1). A value of 1.0 means the output varies significantly over one standard deviation of the input. Leave at 1.0 — the optimizer adjusts it automatically. If model accuracy is poor after training, don't change this — check data quantity (Step 1 health card) or the Data Explorer for non-linear features instead.

A small number that keeps the GPR math solver stable. For clean CFD output (deterministic solvers), the default 1e-6 is correct — do not change it. Only increase if your solver has convergence scatter or you're fitting wind-tunnel data with real measurement noise. Values above 0.1 will visibly smooth predictions and reduce accuracy.

Hyperparameters are auto-optimized via L-BFGS-B (5 random restarts). Optimized values are shown after training.
RF Hyperparameters

Use depth 5 for most datasets. Use depth 3 if your training R² is much higher than your test R² (overfitting). Use depth 10 only for large, clean datasets (300+ runs).

Minimum CFD runs in each prediction region. Higher values create a smoother surrogate surface with less local detail. Use 2–5 if your data has measurement or convergence scatter.

Will train 200 trees. After training, feature importance scores show which inputs most affect your predictions. Faster than GPR on large datasets.

Holds back a random subset of your CFD runs as a proof test. The model never sees these runs during training — fit quality (R²) in Step 3 is measured on this held-back set. A reliable surrogate performs well on both.

20% is a good default (e.g. 77 training / 19 test from 96 runs). Use 10–15% if you have fewer than 40 runs — you need enough training data for the model to learn the response surface.

Test: 20%

Divides your data into k groups. The model is trained and tested k times, each time using a different group as the test set. The CV score is the average R² across all k test folds — a more reliable accuracy estimate than a single split, at the cost of k× longer training time.

Recommended when you have fewer than 50 simulation runs. For 96+ runs a single 80/20 split is usually sufficient. For very small datasets (fewer than 20 runs), use k=3. For 50+ runs, k=5 is usually sufficient.

Rescales all input features to the same numerical range (mean=0, std=1) before training. Essential for GPR and Linear Regression — without it, an angle-of-attack in degrees (0–20) would dominate a Mach number (0.2–0.8) just because its numbers are larger.

Not required for Random Forest (tree splits are scale-invariant) but kept on for consistency. Leave checked — unchecking is only relevant if you intentionally want the model to treat larger-scale inputs as more important, which is almost never what you want.
